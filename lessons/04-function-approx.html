Function Approximation

Tabular methods store a number per state(-action). Real problems have astronomical state spaces — we instead parameterize $Q(s,a;\theta)$ or $V(s;\theta)$ and update θ from samples.

Why approximate?

  • Generalize: nearby states share information.
  • Memory: store weights, not a table.
  • Continuous states: positions, velocities, pixels.

Linear function approximation

v̂(s, w) = φ(s)ᵀ w = Σᵢ φᵢ(s) wᵢ

Features φ can be polynomials, RBFs, or tile coding (multiple overlapping tilings). Linear FA is convex in w for prediction — nice theory — but control with bootstrapping can still diverge.

Semi-gradient TD / Q-learning

TD(0) for V:

w ← w + α [ R + γ v̂(S', w) − v̂(S, w) ] ∇w v̂(S, w)

Linear FA Q-learning (state-action features φ(s,a)):

w ← w + α [ R + γ maxa' q̂(S', a'; w) − q̂(S, a; w) ] φ(S, a)
Semi-gradient means we do not backprop through the target network/value. That’s intentional (stability, like later DQN targets) but weaker than true gradient TD.

Deadly triad (preview)

Bootstrapping + function approximation + off-policy can diverge. DQN’s fixes (target networks, replay) attack this — Week 5.

  • Bootstrapping: targets use current estimates.
  • FA: generalization couples updates.
  • Off-policy: distribution mismatch.
