從示範 / 偏好反推獎勵

一句話總結。 一般 RL：有獎勵 → 學策略。 IRL 倒過來：有行為 / 偏好 → 反推「他在優化什麼獎勵」→ 可再跑 RL。 聊天模型的 RLHF 就是這條思路的現代版。

把問題倒過來

正向 RL逆向 IRL
已知獎勵規則專家行為 / 偏好
想得到好策略合理的獎勵（可再學策略）
像什麼給零食，教會狗坐下看狗乖乖坐，猜主人想鼓勵什麼
先想一想 · 點選答案

為什麼「從行為反推獎勵」天生不唯一？

完整說明

白話：單看行為，動機往往猜不準。所以 IRL 常搭配正則化或人類偏好。

模仿 vs IRL

  • 行為克隆：像監督學習——這個狀態 → 輸出專家動作。簡單，但走歪後錯誤會滾雪球。
  • IRL / IL：抓「在優化什麼」，並常在自己跑的軌跡上修正。
  • 名詞（聽過就好）：MaxEnt IRL、GAIL、AIRL。

不必給完整示範：只問「哪個更好」

人類比較：行為 A ≻ 行為 B
→ 訓練獎勵模型 RM，使「A 總分 > B 總分」
→ 再用 RL 最大化 RM 的分數
P(A ≻ B) = σ( 總分(A) − 總分(B) )

RLHF 三步

  1. SFT：用高品質問答做監督微調。
  2. 獎勵模型：用成對偏好標籤訓練打分器。
  3. RL（PPO / DPO 一族）：優化 RM 分數，同時 KL 懲罰「離原模型太遠」。

偏好損失的直覺版

import math

def sigmoid(x):
    return 1.0 / (1.0 + math.exp(-x))

# 假設一個超簡單的打分模型：score = w * feature_sum
w = 0.0
# 一筆偏好：人類認為 A 比 B 好
feat_A, feat_B = 5.0, 2.0   # 「好行為」特徵較高
lr = 0.1

for step in range(50):
    score_A = w * feat_A
    score_B = w * feat_B
    # Bradley–Terry：P(A>B) = sigmoid(sA - sB)
    p = sigmoid(score_A - score_B)
    # 我們希望 p → 1（A 被選中）
    loss = -math.log(max(p, 1e-9))
    # 這個 toy 模型的梯度（概念）：讓 w 變大，拉開 sA 與 sB
    grad = -(1 - p) * (feat_A - feat_B)
    w -= lr * grad
    if step % 10 == 0 or step == 49:
        print(f"step={step:02d}  w={w:.3f}  P(A>B)={p:.3f}  loss={loss:.3f}")

print("w 變正後，分數較高的特徵組合會被偏好")
真實 RM 是神經網路，輸入是完整對話； 優化端用 PPO/DPO。但核心故事不變：人類偏好 → 可微分的分數 → RL。
更深一點 · 常見坑
  • 獎勵駭入：智能體找到 RM 漏洞（Goodhart）。
  • 偏好雜訊：標註者不一致。
  • 分佈偏移：RM 只在見過的區域準。
  • 過度優化：RM 分上升、真實品質下降——要 KL / 早停。
