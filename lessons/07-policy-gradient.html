REINFORCE：最經典的想法

照目前策略玩完整一局
→ 每一步算「從這裡開始總共拿多少」Gt
→ 分數高：把當時選的動作機率調高
→ 分數低：機率調低

為什麼 REINFORCE 很「吵」？

完整說明
∇J ≈ Σt ∇ log π(At|St) · Gt

修法：減掉基線 b、用優勢 A、之後 Actor-Critic 學價值當評審。

修法：減掉「普通水準」

改用 (Gt − b)　　b ≈ 這個狀態的平均表現
  • 回報 > 基線 → 鼓勵這個動作。
  • 回報 < 基線 → 抑制。

再進一步用優勢 A：「比平常好多少」。 PPO 實作幾乎都用 GAE——名詞聽過就好。

PPO：防止「一次改太猛」

比率 r = 新策略對這個動作的機率 ÷ 舊機率
r ≈ 1：改動不大；r 很大：這個動作被放超大

目標 = min( r·A ， 把 r 夾在 1±ε 之後 × A )
L = 𝔼[ min( r·A , clip(r, 1−ε, 1+ε)·A ) ]

白話：可以往好動作多走一點，但走得離譜時獎勵變平，不再給甜頭。

最小 REINFORCE（概念版）

import math
import random
import torch
import torch.nn as nn
from torch.distributions import Categorical

class Policy(nn.Module):
    def __init__(self, n_obs, n_actions):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(n_obs, 64), nn.ReLU(),
            nn.Linear(64, n_actions),  # 輸出未歸一化分數
        )
    def forward(self, x):
        return Categorical(logits=self.net(x))

policy = Policy(n_obs=4, n_actions=2)
opt = torch.optim.Adam(policy.parameters(), lr=1e-2)
gamma = 0.99

def run_episode(env):
    """env 自行提供 reset/step，回傳 (log_probs, rewards)"""
    s, _ = env.reset()
    log_probs, rewards = [], []
    for _ in range(500):
        dist = policy(torch.tensor(s, dtype=torch.float32))
        a = dist.sample()
        s2, r, done, trunc, _ = env.step(int(a))
        log_probs.append(dist.log_prob(a))
        rewards.append(r)
        s = s2
        if done or trunc:
            break
    return log_probs, rewards

def reinforce_update(log_probs, rewards):
    # 把每一步的回報 G_t 算出來（從後往前折扣累加）
    G, returns = 0.0, []
    for r in reversed(rewards):
        G = r + gamma * G
        returns.insert(0, G)
    returns = torch.tensor(returns, dtype=torch.float32)
    returns = (returns - returns.mean()) / (returns.std() + 1e-8)  # 簡易基線

    loss = sum(-lp * G for lp, G in zip(log_probs, returns))
    opt.zero_grad()
    loss.backward()
    opt.step()

-log π × G 的意義： G 大 → 降低 loss 的方式是提高這次動作的 log 機率； G 小或負 → 反過來。和「好行為被強化」一致。

動手玩：clip 什麼時候生效

你可以這樣玩：

  1. 優勢 A 調成正 → 我們希望 r 變大。
  2. 一路拉大 r，看「clip 是否生效」何時變「是」。
  3. 比較：未裁剪 r·A 一直線性升；PPO 目標到某點後變平。
  4. A 調負 → 方向反了。ε 調大 → 允許的單步改動更寬。

為什麼聊天模型也用 PPO

  1. 用高品質答案做監督微調（SFT）。
  2. 用人類偏好訓練獎勵模型。
  3. 用 PPO 類方法提高獎勵模型分數，同時懲罰「離原本模型太遠」（KL）。
