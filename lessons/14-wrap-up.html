怎麼把 RL 實驗做好

一句話總結。 RL 專題失敗常不是公式抄錯，而是： 只跑一次就下結論、對照組太弱、沒有拆解實驗。 先設計，再開跑。
自學者怎麼用本週。 當成「看論文 / 評估別人結果」的檢查表：他跑幾個種子？有沒有合理基線？

先設計，再訓練

  • 一句話假設：例如「方法 A 在 X 上比 PPO 更省樣本」。
  • 看什麼數字：最終分數、曲線下面積（AUC）、時間、環境步。
  • 預算：與其 10 個變體各跑 1 次，不如 2 個方法各跑 5 種子。
小挑戰 · 點選答案

新方法只跑 1 個 seed，贏過基線 20%。可以直接寫進結論嗎？

完整說明

建議：mean ± std 陰影、多種子、合理基線、拆解實驗。單條精選曲線是自欺欺人。

至少要有哪些對照

  1. 隨機策略：證明有學到東西。
  2. 公認基線：PPO / SAC + 論文預設（別故意調爛）。
  3. 拆掉你貢獻的那一塊：證明不是錯覺。
  4. （可選）別人論文數字——環境與指標必須完全一致。

統計，但不要自欺

  • 畫 mean ± std/sem 陰影；不要只秀精選的一條。
  • 離群多時可報中位數 / IQM。
  • AUC 衡量「學得多快」，不只看最後一點。
AUC ≈ Σt return(t)　→ 學習速度

多種子實驗模板

import json
import statistics

def train_one(seed, algo="ppo"):
    """回傳最終平均回報。這裡先用假資料示意。"""
    # set_seed(seed); env = gym.make(...); ...
    fake_returns = {0: 210.0, 1: 95.0, 2: 240.0, 3: 180.0, 4: 205.0}
    return fake_returns[seed]

results = {s: train_one(s) for s in range(5)}
vals = list(results.values())
print("每個 seed:", results)
print("mean =", statistics.mean(vals))
print("std  =", statistics.pstdev(vals))

# 記錄檔至少要有：
meta = {

    "git_sha": "fill-me",
    "note": "不要只記最好看的那條",
}
print(json.dumps(meta, ensure_ascii=False))

報告骨架

  1. 問題與主張（一句話）
  2. 相關工作（3–5 行）
  3. 方法（直覺 + 一張圖）
  4. 實驗設定（環境、預算、種子）
  5. 結果 + 拆解
  6. 限制（具體）
