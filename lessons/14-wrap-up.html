總結：如何做好 RL（實驗設計）

多數 RL 專題失敗不是「公式寫錯」，而是 變異不受控、基線太弱、缺少消融。

先設計，再訓練

  • 問題：一句話假設（「X 在 Y 上提升樣本效率」）。
  • 因子：演算法、種子、環境套件、要掃的超參數。
  • 指標：最終回報、學習曲線 AUC、牆鐘時間、環境步數。
  • 預算：能負擔多少 run；寧可多種子也不要華麗變體。

重要的基線

  1. 隨機策略 / 腳本啟發式。
  2. 經典無模型基線（PPO 或 SAC）+ 論文預設。
  3. 你的貢獻的消融（拿掉一個元件）。
  4. 可選：近期論文數字——僅當環境/指標一致。

統計，但不要自欺

  • ≥5 個種子支撐主結論（便宜則 10+）。
  • 畫 mean ± std/sem 陰影；絕不只秀一條挑過的 run。
  • 離群值多時報告 IQM / 中位數（rliable 風格）。
  • 先聲明哪些比較是驗證性、哪些是探索性。
AUC = Σt return(t)  →  衡量學習速度，不只終點

報告 / 論文骨架

  1. 問題與主張
  2. 相關工作（3–5 行）
  3. 方法（公式 + 一張圖）
  4. 實驗設定（環境、預算、種子）
  5. 結果 + 消融
  6. 限制（要具體）
